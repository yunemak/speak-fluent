Speak Fluent

A private English conversation partner that runs on your own machine: your browser hears you, a local model replies, a local voice speaks, and the finished conversation is saved as readable Markdown.

The pieces

Browser: microphone capture, Silero voice-activity detection, playback, transcript, report, and history sidebar. Python service: Whisper recognition, Ollama requests, Kokoro speech, and Markdown storage. Ollama: Qwen3 4B for conversation and Qwen3 8B for feedback.

  1. You speakBrowser audio + Silero VAD → frontend/src/lib/audio.js and conversation.js
  2. WordsPOST /api/transcribe → faster-whisper in backend/speech.py
  3. ReplyPOST /api/reply → backend/llm.py → local Ollama Qwen3 4B
  4. VoicePOST /api/speech → backend/voice.py → Kokoro, 9 kHz low-pass, WAV
  5. Feedback“Goodbye” → POST /api/report → Qwen3 8B → backend/history.py Markdown

One action, end to end: the AI speaks

This is the route to follow when the voice, its delay, or its clarity needs work. It is the exact path used to remove the 9–12 kHz static.

1. The browser asks for audio

frontend/src/lib/conversation.js → Conversation.respond → this.api.speech(...)

The conversation controller receives the reply text, splits long feedback into chunks, and asks frontend/src/lib/api.js for /api/speech. While one chunk plays, it can request the next so feedback does not pause.

2. Python turns text into WAV

backend/app.py → @app.post("/api/speech") → backend/speech.py → Speech.synthesize

The endpoint validates the request and runs synthesis as CPU-bound work under voice_lock. That serialization keeps two audio requests from loading the voice engine at the same time.

3. Kokoro speaks, then mastering cleans it

backend/voice.py → Voice.synthesize → Voice._kokoro → Voice._master → Voice._low_pass

Kokoro creates 24 kHz float samples with the selected voice (af_heart by default). The 127-tap, 9 kHz linear-phase low-pass removes the hot 9–12 kHz band heard as static. DC removal, 0.9 peak normalization, and 8 ms fades follow. wav_bytes turns the result into PCM16 WAV; the browser decodes and plays it.

Useful search anchors

grep -n "def _low_pass" backend/voice.py · grep -n "@app.post(\"/api/speech\")" backend/app.py · grep -n "this.api.speech" frontend/src/lib/conversation.js

To change this, start here

Voice character

Set SPEAK_FLUENT_VOICE or change VOICE_NAME in backend/config.py. Available voices and setup notes are in models/README.md; scripts/compare_voices.py renders local samples.

Voice brightness or hiss

Adjust the cutoff or tap count in Voice._low_pass in backend/voice.py. Re-run the real /api/speech check and listen before keeping a change.

Conversation style

Edit the conversation and opening prompts in backend/prompts.py; the request flow is llm.reply in backend/llm.py.

Feedback wording

Start in backend/prompts.py for the review instructions, then backend/llm.py for report, grounding in validate_feedback, and format_feedback.

Saved-conversation UI

frontend/src/components/HistoryView.jsx renders the saved view; frontend/src/components/Transcript.jsx is shared by live and saved conversations.

Start screen and status

Labels, the tagline, and the start button live in frontend/src/components/ConversationView.jsx; the shell and history wiring live in frontend/src/App.jsx.

A practice to reuse

The project moment: the AI voice had a static hiss. Instead of guessing at the browser or changing the model, the exact /api/speech WAV was measured. Full-precision and int8 Kokoro were compared; Chromium's 24 → 48 kHz decode was checked for imaging; then the spectrum showed an unusually hot 9–12 kHz band in af_heart. One mastering stage changed, and the same measurements plus a Whisper transcription and the browser journey confirmed the result.

Reusable practice: when output is wrong, capture the real artifact and measure each stage before changing a layer. Keep a before/after check that exercises the same thing the user will experience. That is faster and safer than changing several plausible causes at once.

Run it again

# 1. Ollama (from the project root)
OLLAMA_NO_CLOUD=1 OLLAMA_HOST=127.0.0.1:11434 ollama serve

# 2. Python service
.venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000

# 3. Interface
npm --prefix frontend run dev -- --host 127.0.0.1 --port 5173 --strictPort

Open http://127.0.0.1:5173. Full setup and troubleshooting are in README.md; saved conversations are under data/conversations/.
